# 🤖 iГрамотей v5

**iГрамотей** — Telegram-бот для интеллектуальной обработки текста. Транскрибирует голосовые сообщения и кружочки, распознаёт текст с изображений (OCR), читает документы и веб-страницы, извлекает субтитры YouTube — и предлагает несколько режимов обработки с экспортом результата.

---

## 🚀 Возможности

### 🎙️ Транскрибация
- **Голосовые сообщения** и **кружочки** — распознавание речи через Whisper (Groq)
- Ротация пула API-ключей с обработкой Rate Limit

### 📄 Работа с файлами и изображениями
- **OCR** — распознавание текста с фото и скриншотов через Groq Vision
- **PDF** — извлечение текста и таблиц через `pdfplumber` (async, не блокирует event loop)
- **DOCX** — чтение документов Word через `python-docx`
- **TXT / LOG / RST / TEX** — UTF-8 (в т.ч. BOM), UTF-16, CP1251, KOI8-R, CP866
- **MD** (Markdown) — читается как есть, YAML front matter отбрасывается
- **HTML / HTM** — видимый текст страницы без скриптов и стилей
- **ODT, RTF, EPUB, FB2** — без внешних зависимостей
- **SRT / VTT** — субтитры без номеров и таймингов
- Неизвестные расширения — если внутри обычный текст, читаются как TXT

### 🌐 Веб и YouTube
- **Ссылки** — скрейпинг страницы, автоматическое саммари, полный набор режимов обработки
- **YouTube** — субтитры без авторизации и куки через `youtube-transcript-api`; если субтитров нет — честный отказ без попытки транскрибировать аудио; LLM форматирует субтитры в диалог и вырезает рекламные интеграции (`[реклама вырезана]`)

### ✍️ Режимы обработки текста
- 📝 **Как есть** — минимальная коррекция: опечатки, пунктуация, регистр. Голос автора сохранён полностью
- ✨ **Красиво** — редактура: убирает слова-паразиты, повторы, выравнивает структуру. Текст остаётся авторским
- 📊 **Саммари** — аналитический пересказ от третьего лица с сохранением всех фактов и деталей
- ✏️ **Работа над ошибками** — разбор каждой правки с объяснением (доступно после «Как есть» и «Красиво»)
- 💬 **Диалог по документу** — вопросы к содержимому текста со стримингом ответа (в режиме саммари)
- 🌐 **Перевод на русский** — появляется автоматически когда язык текста явно не русский; переключение туда и обратно без потери оригинала

### 💾 Экспорт
- Выгрузка результата в **TXT**, **PDF** (reportlab) или **DOCX**

## 📦 Установка и запуск

### 1. Системные зависимости
```bash
sudo apt-get update && sudo apt-get install -y ffmpeg
```

### 2. Python-пакеты
```bash
pip install -r requirements.txt
```

### 3. Переменные окружения (`.env`)
```env
BOT_TOKEN=ваш_токен_телеграм_бота
GROQ_API_KEYS=ключ1,ключ2,ключ3          # Whisper, OCR и запасной откат
OPENROUTER_API_KEYS=sk-or-...             # текстовые LLM (можно несколько через запятую)
# необязательно: свой порядок моделей (через запятую, первая — основная)
# OR_MODELS_BASIC=nvidia/nemotron-3-super-120b-a12b:free,nvidia/nemotron-3-ultra-550b-a55b:free
# OR_MODELS_PREMIUM=...  OR_MODELS_SUBTITLES=...  OR_MODELS_REASONING=...
# YandexGPT (необязательно). Включает профили «Yandex (с fallback)» и «Yandex (only)» в /model
# YANDEX_API_KEY=...         # API-ключ сервисного аккаунта (роль ai.languageModels.user)
# YANDEX_FOLDER_ID=b1g...    # ID каталога
# YANDEX_MODELS=yandexgpt-5.1,yandexgpt-lite   # по приоритету; имя дополняется до gpt://<folder>/<имя>
# YANDEX_BASE_URL=https://llm.api.cloud.yandex.net/v1   # или https://ai.api.cloud.yandex.net/v1
# YANDEX_TIMEOUT=30  YANDEX_MAX_CONCURRENT=8   # таймаут, сек; одновременных запросов (квота — 10)
# YANDEX_BREAKER_FAILS=3  YANDEX_BREAKER_PAUSE=120   # после 3 сбоев подряд Yandex пропускается на 120 с
# APP_LLM_PROFILE=yandex   # модель правки для Android-приложения: yandex (с откатом), yandex_only, auto… (речь всегда на Groq)
# YANDEX_DATA_LOGGING=0      # 1 — разрешить Яндексу логировать запросы (по умолчанию запрещено)
SUPABASE_URL=https://xxx.supabase.co   # опционально
SUPABASE_KEY=ваш_anon_ключ             # опционально
PORT=8080

# Доступ и лимиты
ADMIN_IDS=123456789                       # ваш Telegram ID (несколько — через запятую)
# необязательно, значения по умолчанию в скобках:
# USER_DAILY_LIMIT=30        # обращений к ИИ в сутки на пользователя
# USER_MAX_FILE_MB=10        # размер файла или фото
# USER_MAX_AUDIO_SEC=300     # длина голосового, кружка, аудио
# USER_MAX_TEXT_CHARS=15000  # длина присланного текста
# USER_COOLDOWN_SEC=3        # пауза между сообщениями
# GROUP_DAILY_LIMIT=40       # обращений к ИИ в сутки на каждый групповой чат
# LIMITS_TZ=Europe/Minsk     # сутки считаются по этому поясу, сброс в 00:00
# OR_MODELS_IMG2PROMPT=nvidia/nemotron-3-nano-omni-30b-a3b-reasoning:free,thinkingmachines/inkling-small:free   # vision-модели для /img2prompt
# GROQ_VISION_MODELS=qwen/qwen3.8-27b,qwen/qwen3.6-27b   # vision на Groq (OCR): основная и запасная
# (в /model показываются только рабочие модели: список сверяется с провайдерами раз в 10 минут)
# DEFAULT_LLM_PROFILE=auto   # модель по умолчанию: auto, nemotron_super,
#                            # nemotron_ultra, groq, yandex, yandex_only
```

> Без `SUPABASE_URL` / `SUPABASE_KEY` бот работает без базы данных — история `/history` недоступна, всё хранится в памяти процесса.

### 4. Запуск
```bash
python bot.py
```

## 🗄️ SQL для Supabase

```sql
CREATE TABLE IF NOT EXISTS users (
    id BIGINT PRIMARY KEY,
    username TEXT,
    first_name TEXT,
    first_seen TIMESTAMPTZ DEFAULT NOW(),
    last_seen TIMESTAMPTZ DEFAULT NOW()
);

CREATE TABLE IF NOT EXISTS transcripts (
    id BIGSERIAL PRIMARY KEY,
    user_id BIGINT REFERENCES users(id) ON DELETE CASCADE,
    source_type TEXT NOT NULL,
    original_text TEXT NOT NULL,
    created_at TIMESTAMPTZ DEFAULT NOW()
);

CREATE TABLE IF NOT EXISTS results (
    id BIGSERIAL PRIMARY KEY,
    transcript_id BIGINT REFERENCES transcripts(id) ON DELETE CASCADE,
    mode TEXT NOT NULL,
    result_text TEXT NOT NULL,
    created_at TIMESTAMPTZ DEFAULT NOW()
);

CREATE INDEX IF NOT EXISTS idx_transcripts_user_id ON transcripts(user_id);
CREATE INDEX IF NOT EXISTS idx_transcripts_created_at ON transcripts(created_at DESC);
CREATE INDEX IF NOT EXISTS idx_results_transcript_id ON results(transcript_id);
```

Таблицы для лимитов и настроек модели (необязательно — без них всё работает на памяти процесса, после рестарта счётчики обнуляются):

```sql
CREATE TABLE IF NOT EXISTS bot_settings (
    key TEXT PRIMARY KEY,
    value TEXT NOT NULL,
    updated_at TIMESTAMPTZ DEFAULT NOW()
);

CREATE TABLE IF NOT EXISTS usage_daily (
    user_id BIGINT NOT NULL,
    day DATE NOT NULL,
    count INT NOT NULL DEFAULT 0,
    PRIMARY KEY (user_id, day)
);
CREATE INDEX IF NOT EXISTS idx_usage_daily_day ON usage_daily(day);
```

## 🎨 Картинка → промпт

Три способа запустить: команда `/img2prompt` и затем картинка (режим держится 10 минут, можно слать несколько подряд, выход — `/cancel`); подпись «промпт» (или `/prompt`) к фото; ответ командой `/prompt` на любое фото. Принимаются фото и картинки файлом (JPG, PNG, WEBP и др.).

В ответе: основной промпт, короткая версия, negative (если применим) и описание по-русски. Кнопки под результатом переключают стиль: **универсальный** (FLUX, DALL·E, Imagen), **Midjourney** (с `--ar` по реальным пропорциям картинки), **Stable Diffusion** (теги, веса, negative) и **описание по-русски**; «Другой вариант» перегенерирует. Промпты нажатием копируются.

**Подробность** (отдельный ряд кнопок): 📏 кратко (~150–350 знаков, только главное), 📐 средне (~500–900, по умолчанию) и 📚 подробно (~1200–2000, слои фона, материалы, оптика, свет, палитра, мелкие детали и надписи). Рядом с названием стиля показывается фактическая длина в знаках. Модели попадают в диапазон приблизительно, поэтому слишком длинный ответ (больше max × 1,25) аккуратно обрезается по границе предложения или запятой, а параметры Midjourney в конце строки сохраняются. Диапазоны и тексты уровней меняются в `config.IMG2PROMPT_DETAILS`. Выбранная подробность запоминается для следующих картинок (в Supabase, если он подключён). Каждая комбинация «стиль × подробность» кэшируется отдельно: повторное переключение на уже готовую бесплатно. Уже сгенерированные стили переключаются бесплатно, каждая новая генерация стоит 1 единицу лимита.

Модели: цепочка vision-моделей OpenRouter из `OR_MODELS_IMG2PROMPT` (по умолчанию Nemotron 3 Nano Omni, затем Inkling Small), при сбоях откат на Groq (`GROQ_MODELS["vision"]`). Выбор `/model` на эту функцию не влияет. Если модель отключат, достаточно поменять переменную окружения. Проверенная запасная: `nvidia/nemotron-3-nano-omni-30b-a3b-reasoning:free` (бесплатный эндпоинт NVIDIA логирует запросы и не рекомендует слать лица людей).

## 🎭 Стили, 🔍 diff, 📋 протокол, 👥 диалог по ролям

**Стили правки** (кнопка «🎭 Стиль…» под результатом и под первым выбором режима): 💼 деловой, 💬 разговорный, ✂️ короче, 📖 подробнее, 📣 пост для канала, ✉️ официальное письмо. Это обычные режимы: результат кэшируется, переключается и экспортируется как остальные. Тексты стилей — в `config.EDIT_STYLES`.

**🔍 Что изменилось** показывает наглядный diff между оригиналом и результатом: зачёркнуто — удалено, жирным — добавлено, сверху число правок. Считается обычным кодом, **лимит не тратит**. У длинных текстов показываются только изменённые места с контекстом.

**📋 Протокол** (для текстов от ~80 слов) собирает из встречи или голосового: тему, суть, решения, задачи в формате «что — кто — срок», открытые вопросы и договорённости по времени. Ничего не додумывает: если исполнитель или срок не названы, так и пишет.

**👥 Диалог** (от ~25 слов) разбивает расшифровку на реплики «Говорящий 1», «Говорящий 2» и т. д. Работает для голосовых, кружков, аудио, видео и диктофонных записей. Кнопка **«Назвать собеседников»** подставляет имена (`Анна, Игорь` или `1=Анна, 2=Игорь`) без обращения к ИИ.

> ⚠️ Whisper не различает голоса, поэтому роли определяет языковая модель **по смыслу** (вопрос — ответ, обращения, реакции). На коротких диалогах двух людей это работает хорошо, на записях с похожими репликами или тремя и более участниками возможны ошибки, о чём бот предупреждает в конце. Настоящее распознавание по голосу (diarization) требует тяжёлых моделей и серверных ресурсов, на бесплатном хостинге оно нереально. Длинные записи обрабатываются частями (по ~5000 знаков, максимум 6 частей); каждая часть стоит 1 единицу лимита.

## 👥 Работа в группах

Добавьте бота в чат. **Чтобы он видел все голосовые, отключите Group Privacy:** @BotFather → `/setprivacy` → ваш бот → `Disable` (или сделайте бота администратором группы). Без этого бот видит только команды и ответы на свои сообщения.

- `/autovoice on` — бот сам расшифровывает голосовые и кружки и отвечает текстом с кнопками (✨ Красиво, 📊 Саммари, 📋 Протокол, 👥 Диалог). Включать и выключать могут админы чата; настройка хранится в Supabase.
- Ответом на сообщение: `/fix`, `/summary`, `/protocol`, `/dialogue` — для текста, голосового, кружка, видео и аудиофайла.
- **Лимит**: общий на чат (`GROUP_DAILY_LIMIT`, по умолчанию 40 в сутки), остаток — `/limit` в группе; сообщения администратора бота ничего не списывают. Когда лимит кончился, бот один раз за сутки сообщает об этом и дальше молчит. Индивидуальный лимит чату: `/setlimit <id чата> число`.
- Слишком длинные и большие записи при авто-режиме молча пропускаются (потолки как у обычных пользователей).
- Всё остальное в группах бот игнорирует.

## ✏️ Inline-режим

Напишите в любом чате `@имя_бота ваш текст` и выберите вариант: «Как есть», «Красиво», «Деловой», «Разговорный», «Короче», «На русский». Telegram ограничивает inline-запрос **256 символами**, поэтому режим подходит для коротких фраз. Сам поиск вариантов ничего не стоит; обработка списывает 1 единицу у того, кто нажал.

Настройка в @BotFather: `/setinline` → задайте подсказку (например, «Текст для исправления»). Дополнительно, но желательно: `/setinlinefeedback` → `Enabled` (100%), тогда выбранный вариант обрабатывается сразу; без этого в отправленном сообщении появляется кнопка «▶️», которую нужно нажать (кнопка работает всегда как запасной вариант).

## 🧠 Цепочка моделей и fallback

Все текстовые задачи (коррекция, «Красиво», саммари, перевод, разбор правок, диалог по документу, субтитры) идут по цепочке. Whisper (речь) и OCR остаются на Groq.

| Профиль в `/model` | Порядок |
|---|---|
| 🤖 Авто | Nemotron 3 Super → Nemotron 3 Ultra (OpenRouter, бесплатно) → Groq `gpt-oss` |
| 🟡 Yandex (с fallback) | YandexGPT 5.1 → YandexGPT Lite → цепочка «Авто» |
| 🟡 Yandex (only) | только YandexGPT, без подмены: при сбое будет ошибка |
| 🔬 Nemotron Super / 🏔 Nemotron Ultra | одна конкретная модель, строго |
| ⚡ Groq gpt-oss | только Groq |

**YandexGPT** подключается переменными `YANDEX_API_KEY` и `YANDEX_FOLDER_ID` (API-ключ сервисного аккаунта с ролью `ai.languageModels.user`). Работает через OpenAI-совместимый API (`YANDEX_BASE_URL`), модели задаются `YANDEX_MODELS` (имя дополняется до `gpt://<folder>/<имя>`). Без ключей профили Yandex в `/model` не показываются, а бот работает как раньше.

**Защита от сбоев:**
- таймаут `YANDEX_TIMEOUT` (30 с) и не более `YANDEX_MAX_CONCURRENT` одновременных запросов (квота Яндекса — 10 синхронных);
- **предохранитель**: после `YANDEX_BREAKER_FAILS` сбоев подряд Yandex пропускается на `YANDEX_BREAKER_PAUSE` секунд, чтобы пользователь не ждал таймаут на каждом запросе;
- **отказ модели** (фильтр контента YandexGPT на «чувствительные» темы) не считается сбоем: текст получает запасная модель;
- **мёртвые модели**: ответ 404 (модель снята, бесплатный вариант отозван) отключает модель на час, чтобы не терять запрос на каждой попытке;
- запросы Яндексу на логирование запрещены по умолчанию (`YANDEX_DATA_LOGGING=0`).

**В `/model` только рабочие модели.** Список моделей у OpenRouter и Groq запрашивается при старте и при открытии `/model` (не чаще раза в 10 минут). Профиль скрывается, если его модели нет у провайдера, она недавно отвечала 404 или провайдер не настроен; причина показана под меню. Если список провайдера получить не удалось, ничего не скрывается. Временный лимит 429 моделью-неработающей не считается.

**Проверка:** `/llmcheck` (админ) отправляет короткий запрос каждому звену цепочки и показывает время ответа, а ниже сверяет все модели из настроек с живыми списками провайдеров. При старте та же сверка идёт в лог (`⚠️ МОДЕЛЬ: …`). Если бесплатную модель снимут, в логе и в `/llmcheck` об этом будет прямо написано.

Бесплатные модели OpenRouter меняются часто; цепочки можно переопределить без правки кода (`OR_MODELS_BASIC`, `OR_MODELS_PREMIUM`, `OR_MODELS_SUBTITLES`, `OR_MODELS_REASONING`).

## 📱 API для Android-приложения

Приложение [iGramotey_app](https://github.com/inikonoff/iGramotey_app) (плавающий виджет диктовки) обращается к серверу по двум эндпоинтам. Оба требуют заголовок `X-App-Token` (значение `APP_SECRET_TOKEN`).

| Эндпоинт | Что делает |
|---|---|
| `POST /api/dictate` (multipart, поле `file`) | Распознавание речи (Groq Whisper, **всегда**) → правка текста → чистый текст |
| `POST /api/correct` (JSON `{"text": "..."}`) | Только правка текста |

Правка текста для приложения идёт по профилю **`APP_LLM_PROFILE`** (по умолчанию `yandex`: YandexGPT с откатом на запасные модели), независимо от выбора в `/model`. Режим правки задаёт `APP_CORR_STYLE`: `premium` («Красиво», по умолчанию) или `basic` («Как есть»). Значения профиля: `yandex`, `yandex_only` (без запасных), `auto`, `groq` и другие ключи `/model`. Запросы приложения не списывают пользовательский лимит. Ответ: `{"status": "success", "text": "..."}`.

Бесплатный хостинг (Render) засыпает без запросов. Чтобы не ждать холодный старт, настройте внешний пингер (UptimeRobot, cron-job.org) на `/ping` раз в 10 минут.

## 👑 Администратор, лимиты и выбор модели

**Администратор** задаётся переменной `ADMIN_IDS`. У него нет лимитов, и только ему доступны `/model`, `/llmcheck`, `/admin`, `/setlimit` и `/status`. Если `ADMIN_IDS` не задан, лимиты действуют на всех, включая владельца (в логе будет предупреждение).

**Лимиты обычных пользователей.** Единица лимита — одно обращение к ИИ: распознавание голоса или фото, обработка текста, перевод, разбор правок, вопрос по документу, форматирование субтитров. Бесплатны: команды, просмотр уже готовых (кэшированных) результатов, экспорт, уже закэшированные субтитры YouTube. Ошибки и отказы по лимиту не кэшируются, их можно повторить. Дополнительно действуют потолки на одно сообщение (размер файла, длина голоса, длина текста) и пауза между сообщениями. Лимит сбрасывается в 00:00 по `LIMITS_TZ`.

**Выбор модели** (`/model`, только админ) меняет модель для текстовых задач; Whisper и OCR всегда на Groq. Админ выбирает личный вариант, может сделать его общим для всех или сбросить. В списке только рабочие модели (см. «Цепочка моделей»). Профиль «Авто» сам переключается между моделями OpenRouter и откатывается на Groq; «Yandex (с fallback)» начинает с YandexGPT; конкретная модель и «Yandex (only)» работают строго: если модель недоступна, будет ошибка, а не подмена. Выбор сохраняется в Supabase (`bot_settings`), без БД действует до рестарта; значение по умолчанию задаёт `DEFAULT_LLM_PROFILE`.
